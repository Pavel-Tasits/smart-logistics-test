# AI Usage

## Какие части делались с AI

- Первичный каркас проекта (Vite + TS, конфиги, tsconfig, структура FSD).
- Генерация типов из OpenAPI (`openapi-typescript`) и написание слоёв поверх них:
  HTTP-клиент, обработка ошибок, TanStack Query-обёртки.
- Черновая версия OpenAPI-схемы (пока настоящей не было) и последующая **полная
  миграция** кода на реальную схему.
- Реализация MSW-моков (стейтовый стор, seed с edge cases, обработчики),
  ViewModel-мапперов, фильтров с синхронизацией в URL, формы ставки, виджетов.
- Unit-тесты и документация.

## Какие решения принял сам (не AI по умолчанию)

- **Стек-развилки:** Mantine как UI-кит, MobX для UI-state, форма ставки как
  **отдельный роут + модалка** (требование «открывается по ссылке»).
- **Слой ViewModel + мапперы** как способ изолировать UI от «шумного» DTO
  реальной схемы — вместо того чтобы тащить сырые вложенные DTO в компоненты.
  Это же дало естественные единицы для тестов, которые просит задание.
- **Трактовка неоднозначных фильтров** строго по схеме: задание перечисляет
  `status` и `statuses` — сопоставил их с реальными полями контракта:
  `status` = торговый статус пользователя (строки), `statuses` = статус аукциона
  (числовые коды). `auc_type` — мультивыбор (в схеме это массив).
- **Единый источник правды для цен/направления торгов** (`shared/mocks/trading.ts`):
  клиентская zod-валидация формы и серверная валидация мока используют одну и ту
  же чистую функцию `validateBidPrice`, чтобы контракт 422 совпадал.
- **Идентичность текущего пользователя** вынесена в `CURRENT_USER`
  (`shared/config`) и переиспользуется мок-сидом и маппером `is_mine`.
- **Функционал изменения ставок** переписал (типизация, бизнес-логика, корнер-кейсы)
- **Функционал изменения фильтров** добавил replace: true в router.tsx, чтобы не засорять history
- AuctionActions вынесен в отдельный компонент
- из AuctionDetailWidget вынесены компоненты в отдельные файлы

## Какие AI-предложения отклонил

- Черновая (самодельная) OpenAPI-схема как «источник правды» — заменена на
  предоставленную реальную; весь код переориентирован на неё.
- Первоначальный код был написан под Mantine v7 API (`Grid gutter`, `Collapse in`).
  Установилась Mantine v9 с переименованными пропсами — исправил (`gap`,
  `expanded`) вместо даунгрейда.
- Использование `component={Link}` у Mantine-кнопок (ломает generic-типизацию
  роутера) — заменено на `renderRoot`, чтобы `to/params` оставались типобезопасными.
- Хранение фильтра городов по имени — заменил на `city_gc_id` из схемы.

## Что проверял особенно внимательно

- **Соответствие реальному контракту:** имена полей, вложенность, enum-значения,
  nullable, формат ошибок `problem+json`, `POST /bets` без тела ответа.
- **Стейтовость мока:** что `setBet` действительно пересчитывает `place`,
  текущую цену, `status_mobile`, `your.bet` и что инвалидация обновляет
  список/детальную/ставки.
- **Search params:** безопасные fallback (битый URL не роняет страницу),
  корректный маппинг статусов аукциона в числовые коды.
- **Edge cases** из задания: скрытая история ставок, скрытая цена груза,
  скрытые адреса/контакты, отменённые ставки, `can_set_bet=false`, пустые состояния.

## Оставшиеся риски

- Направление/ранжирование торгов и вывод «доступной цены» в моках —
  разумная, но собственная модель (в схеме нет полной бизнес-логики торгов);
  на реальном бэкенде поведение может отличаться.
- `is_available` в detail отсутствует в схеме — выведено эвристически.
- E2E-проверка потока в реальном браузере делалась вручную; автоматических
  браузерных тестов нет.
- Не покрыты все второстепенные поля схемы (контейнеры, встречные ставки,
  ассамблеи) — показаны только релевантные заданию.

## Что улучшил бы за ещё один день

- Компонентные/интеграционные тесты (Testing Library) на форму ставки и список,
  и браузерный e2e (Playwright) на ключевой поток «фильтр → детальная → ставка».
- Оптимистичные апдейты и обработка гонок при установке ставки.
- Код-сплиттинг (сейчас один крупный бандл) и вынос MSW из прод-сборки.
- Полноценные состояния 401/503 (ре-логин, ретраи) и i18n.
- Доступность (фокус-менеджмент в модалке, aria) и покрытие тёмной темы.
